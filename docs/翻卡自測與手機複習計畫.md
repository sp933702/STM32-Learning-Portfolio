## 1. 目的與現況

### 1.1 要解決什麼

現在的複習只有一種：到了複習日，在電腦上按「複習」取得提示詞，貼到 Claude 做 15 分鐘的口頭測驗。它考得深，但有兩個限制：

- 每次都要開 Claude、貼提示詞，五分鐘的零碎時間用不上。
- 一定要坐在那台電腦前。

這份計畫加兩件事來補：

| 項目 | 一句話說明 |
|---|---|
| 翻卡自測 | 在 App 裡直接翻卡：看題目、自己先講、翻答案、自評。不需要 Claude |
| 手機複習 | 同一批卡片在手機上也能看、也能翻 |

Claude 的口頭測驗照舊保留。翻卡負責「常常回想」，口頭測驗負責「追問到講得清楚」，兩者不互相取代。

### 1.2 目前有什麼材料（2026-11-13 的資料）

| 材料 | 數量 | 能不能直接當卡片 |
|---|---|---|
| 【面試】卡 | 0 則 | 可以，但現在還沒有。之後每課收尾和每次複習都會產生 |
| 踩過的錯（【問題】） | 49 則 | 可以。標題當題目，內文當答案 |
| 已完成課題的必學項目 | 27 項（4 課） | 可以當題目；答案要從總整理筆記找 |
| 筆記、解法 | 114 則，其中多數第 2 行有粗體的一句話重點 | 可以，但品質不一，預設不放 |

重點：**面試卡現在是 0 則**。如果卡片只來自面試卡，功能做好也沒東西可翻。所以卡片來源要包含踩過的錯與必學項目，並且提供一個補面試卡的方法（5.1 的最後一步）。

### 1.3 已經確認的限制

- GitHub repo 是 `sp933702/STM32-Learning-Portfolio`。我從外部打不開它的網頁，看起來是**私人 repo**（請你確認）。這會影響手機方案，見 4.2。
- App 只在電腦上執行（`127.0.0.1`），手機連不到。
- 資料格式只能新增欄位，舊版 App 還要能讀寫同一份 `progress.json`。

## 3. 翻卡自測的設計（電腦上的 App）

### 3.1 卡片從哪裡來

卡片不另外存一份，每次由 `progress.json` 的現有內容組出來。這樣筆記改了，卡片就跟著改。

| 來源 | 正面（題目） | 背面（答案） | 什麼時候進卡堆 |
|---|---|---|---|
| 【面試】卡 | 標題，去掉【面試】 | 內文 | 存入的隔天 |
| 踩過的錯 | 標題，下面加一行提示「當時錯在哪？正確的做法是什麼？」 | 內文 | 存入的隔天 |
| 必學項目 | 「不看筆記，口頭解釋：」加上項目文字 | 這一課總整理筆記裡「必學範圍對照」中對應的那一行；找不到時顯示「這一課還沒有總整理，請到筆記頁對答案」，並附上打開那一課的按鈕 | 課題完成的隔天 |
| 筆記、解法（預設關閉） | 標題 | 內文 | 打開篩選後，存入的隔天 |

不進卡堆的：待解決的問題（還沒有答案）、【本次進度】、【待學】、已併入的課題、舊計畫（HAL）的筆記。

### 3.2 排程

沿用課題複習的規則，執行者可以直接重用 `REVIEW_INTERVALS` 和 `REVIEW_KEEP`。

| 自評 | 意思 | 下次出現 |
|---|---|---|
| 記得 | 不看答案就講得出重點 | 換下一個間隔（1 → 3 → 7 → 21 天，之後每 45 天） |
| 模糊 | 講得出一部分，或想很久 | 同樣的間隔再一次 |
| 忘了 | 講不出來 | 回到隔天；而且這一輪結束前會再出現一次 |

- 同一天對同一張卡評多次，只算第一次。原因：看過答案之後馬上再評「記得」，不代表隔天還記得。
- 「自由練習」模式（3.4）不改排程，面試前想整批重翻時用。

### 3.3 資料怎麼存

在 `progress.json` 最上層新增兩個欄位。最上層的欄位舊版 App 存檔時會保留（`todo_done` 已經驗證過）。

```json
{
  "cards": {
    "e:8f3a1c2b9d": {"lv": 2, "next": "2026-11-20", "last": "2026-11-13", "prev": 1, "n": 3, "miss": 1},
    "m:SPRINT-W01-S03:m2": {"lv": 0, "next": "2026-11-14", "last": "2026-11-13", "prev": 0, "n": 1, "miss": 1}
  },
  "card_log": {"2026-11-13": 12}
}
```

| 欄位 | 意義 |
|---|---|
| 鍵 `e:<筆記 ID>` | 來自筆記的卡（面試卡、踩過的錯、筆記、解法） |
| 鍵 `m:<課題代碼>:<必學項目 ID>` | 來自必學項目的卡 |
| `lv` | 目前在第幾個間隔 |
| `next` | 下次到期日 |
| `last`、`prev` | 最後一次自評的日期，以及那次自評之前的 `lv`。用來做到「同一天只算第一次」 |
| `n`、`miss` | 總共評過幾次、其中幾次是「忘了」 |
| `card_log` | 每天翻了幾張。用來把翻卡的日子算進「最近 4 週的學習日」 |

- 沒有紀錄的卡視為 `lv` 0，到期日是進卡堆那天。
- 筆記被刪除、或類型改成不進卡堆的類型時，存檔時順手清掉對應的紀錄。
- 不在每則筆記上加欄位。原因：必學項目不是筆記，放在同一個地方比較單純。

### 3.4 畫面

**入口**

- 任務頁上方的提醒卡片多一行：「今日自測　12 張到期」和「開始自測（10 張）」按鈕。沒有到期的卡時顯示下次到期日。
- 「複習」分頁上方多一顆「自由練習」，可以選課題、階段、卡片類型。

**翻卡視窗**（一次只顯示一張，視窗蓋住整個畫面）

| 位置 | 內容 |
|---|---|
| 上方 | 進度（3 / 10）、課題代碼與名稱、卡片類型、「結束」 |
| 中間 | 正面。按「顯示答案」之後，下方出現背面（用現有的 Markdown 顯示） |
| 下方 | 顯示答案前：一顆「顯示答案」。顯示之後：「記得」「模糊」「忘了」三顆，以及「編輯這則筆記」 |

- 鍵盤：空白鍵顯示答案；1、2、3 對應記得、模糊、忘了。
- 出卡順序：先面試卡，再依到期日由舊到新；相鄰兩張盡量來自不同課題。
- 一輪結束顯示小結：三種自評各幾張、「忘了」的卡片標題清單、下一批到期日、「再來 10 張」。
- 顯示答案之前不出現任何答案內容，包括粗體的一句話重點。

### 3.5 和其他功能的連結

- **Claude 複習提示詞**：在「之前的複習」下面多一段「翻卡時答不出來的」，列出這一課 `miss` 大於 0 而且 `lv` 是 0 的卡片標題。`review.md` 的題目來源加一行，請 Claude 優先考這些。
- **學習日**：`forecast()` 的「最近 4 週的學習日」把 `card_log` 的日期算進去。
- **總覽**：`learning/README.md` 加一行「卡片：共幾張，今天到期幾張」。
- **補面試卡**：新增一種提示詞「產生面試卡」，給已完成、但面試卡少於 3 則的課題用。內容是必學範圍、踩過的錯的標題與一句話重點、總整理全文；請 Claude 寫 5 到 8 則【面試】卡。這是捷徑，品質不如口頭測驗後整理的卡，所以排在最後做。

## 4. 手機複習的設計

### 4.1 幾種做法的比較

| 做法 | 手機上能做什麼 | 成本 | 私人 repo 能不能用 | 主要缺點 |
|---|---|---|---|---|
| A. 產生一份可以點開答案的 Markdown（`learning/CARDS.md`） | 在 GitHub 網頁或 GitHub App 上看題目，點一下展開答案 | 很小，只多產生一個檔案 | 可以，登入 GitHub 就能看 | 不能自評，也不會安排順序 |
| B. 互動式網頁，放在 GitHub Pages | 和電腦上一樣的翻卡與自評，可以加到主畫面 | 中 | 免費方案不行；而且 Pages 的網頁本身是公開的 | 筆記內容會公開；手機的自評不會傳回電腦 |
| C. 匯出到 Anki | 成熟的間隔複習，可離線，有自己的同步 | 中。要把 Markdown 轉成 HTML，還要多學一套工具 | 可以 | 排程和 App 是兩套；筆記更新後要重新匯入；iPhone 版要付費 |
| D. 把 App 架在家裡常開的機器上（例如樹莓派），手機透過區域網路或 VPN 連 | 完整的 App | 大 | 可以 | 變成兩個地方各跑一個 App，Git 同步衝突的機會變高；還要處理登入保護 |

關於 GitHub Pages 的兩個條件（私人 repo 需要付費方案、網頁本身公開）是我目前的理解，實作前請執行者到 GitHub 文件再確認一次。

### 4.2 建議：分兩個階段

**第一階段：做法 A，現在就可以做。**
成本最低，私人 repo 也能用，而且不需要任何決定。先用它確認「手機上真的會拿出來看」。

**第二階段：做法 B，等 repo 公開之後再做。**
W07-S02「GitHub 作品整理」本來就要把 repo 公開。到那時筆記已經是公開的，放上 Pages 不會多洩漏什麼，而且免費。如果第一階段用下來發現手機幾乎沒在看，第二階段就不用做。

做法 C 和 D 不建議：C 讓排程分成兩套，D 會把已經穩定的同步方式弄複雜。

### 4.3 第一階段的內容：`learning/CARDS.md`

由 `export_markdown()` 在每次存檔時產生，和 `INTERVIEW.md` 一樣不要手動修改。

```markdown
# 翻卡複習

- 產生時間：2026-11-13 21:40（到期的卡以這個時間為準）
- 用法：先自己講一次，再點題目展開答案。自評和排程請回電腦上的 App 做。

## 到期的卡（12 張）

<details>
<summary>為什麼要先開周邊時脈才能設定 GPIO？（GPIO・面試卡）</summary>

**沒有時脈，暫存器的寫入會被忽略**

- F1 的周邊預設不供應時脈以省電

</details>

## 全部卡片

### SPRINT-W01-S03 GPIO（暫存器重做）
…
```

- `<summary>` 後面一定要空一行，裡面的 Markdown（表格、程式碼）才會正常顯示。
- 「到期的卡」最多列 30 張；「全部卡片」依課程順序分組，每課先面試卡、再必學項目、再踩過的錯。
- `learning/README.md` 最上面加連結。
- 檔案大小：目前 76 張卡，估計 40 到 60 KB，可以接受。超過 300 張時改成每個階段一個檔案。

### 4.4 第二階段的內容：互動式網頁（repo 公開之後）

- App 存檔時多產生一個**單一檔案**的網頁 `docs/cards.html`：卡片資料直接寫在檔案裡，翻卡的程式也在裡面，不依賴任何外部服務。
- GitHub Pages 設定成從 `main` 分支的 `/docs` 資料夾發布，並放一個空的 `docs/.nojekyll`。網址會是 `https://sp933702.github.io/STM32-Learning-Portfolio/cards.html`。
- 翻卡畫面和 3.4 相同，按鈕放大，適合單手操作。
- 手機上的自評存在手機瀏覽器裡（`localStorage`），只用來決定手機上的出卡順序，**不傳回電腦**。換手機或清除瀏覽器資料就會歸零。
- Markdown 顯示要和 App 一致：把 `index.html` 裡的 `esc`、`mdInline`、`splitCells`、`md` 這一段用註解標記包起來，產生網頁時由 Python 讀出來放進去，不要另外維護第二份。
- 注意 `docs/` 裡的計畫文件也會跟著被發布。repo 公開之後這不是問題；介意的話把計畫文件移到 `plans/`。

**把手機的自評傳回電腦（選做，不建議一開始就做）**

需要在手機瀏覽器裡存一組 GitHub 權杖，讓網頁把自評紀錄寫進 repo 的 `learning/mobile_log.json`，電腦上的 App 同步時再合併。設計重點如果真的要做：權杖只開這一個 repo 的檔案寫入權限；手機只寫 `mobile_log.json`，不碰 `progress.json`；App 以「卡片鍵加日期」去重，合併可以重複執行。風險是權杖放在手機瀏覽器裡，以及多一條會出錯的同步路徑。等手機真的用得很頻繁再評估。

三批各自獨立，可以分開交付。每一批結束都要執行 `python tracker2/selftest.py` 全部通過，並更新 `docs/APP改進計畫.md` 5.0 之後的紀錄與 `README.md`。

### 5.0 實作進度

| 批次 | 狀態 | 說明 |
|---|---|---|
| A 批：翻卡自測（電腦） | 已完成（2026-11-13），待使用者試用確認 | 見下方「A 批實作紀錄」 |
| B 批：手機第一階段（`CARDS.md`） | **暫緩**（使用者 2026-11-14 決定手機的部分先不做） | 之後要做時可以直接做，不需要再決定什麼 |
| C 批：手機第二階段（互動式網頁） | **暫緩**（同上） | 要做時先回答 D5、D6、D7，而且 repo 要先公開 |

**A 批實作紀錄**

- 使用者的決定（2026-11-13）：三種卡片都做，但要能選擇翻哪一種，以面試卡為主。實作成：開始前勾選類型，**預設只勾面試卡**；勾選會記在這台電腦的瀏覽器資料裡（`localStorage`），下次開啟沿用。D2、D3、D4 照建議做。
- 卡片類型有四種：面試卡、必學項目、踩過的錯、筆記與解法。第四種是 3.1 表格裡「預設關閉」的那一列，同樣用勾選的。
- 卡片由 `build_deck()` 每次從筆記與必學項目組出來，沒有另外存一份。
  - 必學項目只取已完成的技術課題；文字含「驗收」或「總整理」的項目是流程不是題目，不做成卡（例如 SysTick 課的「完成驗收與收尾總整理」）。
  - 必學項目的答案從總整理筆記的「必學範圍對照」比對出對應的那一行（`must_answer()`，比對每一行「：」之前或表格第一格的文字）。比對不到時顯示整段「必學範圍對照」；總整理裡沒有這一段時顯示整則總整理；連總整理都沒有時顯示說明文字和「打開這一課」。目前四課都屬於後兩種情況：C 驗收、時脈、GPIO 沒有總整理，SysTick 的總整理沒有「必學範圍對照」這一段。
  - 只有標題、沒有內文的筆記不做成卡。
- 排程存在 `progress.json` 最上層的 `cards` 與 `card_log`，格式同 3.3，**但沒有 `prev` 欄位**：同一天對同一張卡評第二次時直接不計，用不到它。
- 自評時只寫 `progress.json`，不重新產生 `learning/*.md`（一輪要評很多張）。所以總覽裡的卡片統計要等下一次一般的存檔才更新。
- 出卡順序：先面試卡，其餘依到期日由舊到新（不分類型），相鄰兩張盡量來自不同課題。
- 畫面和 3.4 的差異：入口是任務頁上方獨立的「翻卡自測」卡片，裡面有類型勾選、課題選單、「開始自測」和「自由練習」。自由練習沒有放在「複習」分頁，因為它和開始自測共用同一組勾選。

## 6. 風險與不做的事

| 風險 | 說明 | 對策 |
|---|---|---|
| 做完沒在用 | 這兩天已經花不少時間在 App 上，再加功能會排擠 Startup 課 | A 批做完先用一週再決定 B、C；每一批都可以獨立停下來 |
| 卡片品質 | 踩過的錯的標題不一定像題目（例如「GPIO 設定的兩個誤解」） | 翻卡視窗有「編輯這則筆記」；面試卡累積後，可以把踩過的錯從預設來源拿掉 |
| 自評太寬鬆 | 自己評自己容易給「記得」 | Claude 的口頭測驗保留，它才是把關；翻卡答不出來的會帶進提示詞 |
| 兩套排程負擔太重 | 課題複習加卡片複習，到期的東西變多 | 每次自測上限 10 張；觀察兩週，如果口頭測驗一直積著沒做，再考慮拉長它的間隔 |
| 兩台電腦同時翻卡 | `cards` 會衝突 | 和現在一樣由同步衝突的機制處理；翻卡前先同步 |
| 公開筆記 | Pages 的網頁任何人都看得到 | 等 repo 本來就要公開時才做 C 批 |

不做的事：

- 不做積分、連續天數、徽章。
- 不在 App 裡嵌入 Claude 對話。
- 不把卡片另外存成一份資料；卡片永遠從筆記和必學項目組出來。
- 不為了手機改變電腦上 App 的執行方式（仍然是本機、單一執行個體）。

## 7. 執行者注意事項

完整版在 `docs/APP改進計畫.md` 第 6 節，動手前請先讀。和這份計畫最相關的幾條：

- **不要修改 `tracker/`**（舊版 App）。所有變更都在 `tracker2/`。
- **資料格式只新增欄位**。這次新增的是最上層的 `cards` 和 `card_log`；做完要驗證舊版 App 存檔後它們還在。
- 改完執行 `python tracker2/selftest.py`，全部通過才算完成。
- `index.html` 大量使用樣板字串，內容裡的反引號必須跳脫。
- `learning/` 底下的 `.md` 都由 `export_markdown()` 產生，不要手動改。
- 透過連結的電腦操作時：不要執行 `git commit`、`stash`、`checkout`、`pull`；掛載的資料夾不能取代或刪除檔案，修改用「讀取 → 確認目標字串只出現一次 → 取代 → 寫回」。
- 修改資料或安裝程式前，確認兩個 App 都已關閉（`tracker/.app_port` 和 `tracker2/.app_port` 都不存在）。
- 畫面要實際用無頭瀏覽器跑過一次，不能只做語法檢查。
- 寫給使用者看的文字用繁體中文；不用 ①②③ 或「步驟 2」指涉前文。
- 不要為了壓低提示詞字數而拿掉讓 Claude 掌握進度的內容（2026-11-13 的決定）。
