## 1. 檢視結論（先講最重要的）

### 1.1 進度：計畫和實際速度差距很大，需要重排

| 項目 | 原計畫 | 實際（到 11-12） |
|---|---|---|
| 經過時間 | 8 週中的第 4 週結束 | 同左 |
| 應完成課題 | W01～W04 共 16 課 | 完成 3 課，第 4 課（SysTick）接近完成 |
| 每課花費 | 平均 1.4 天一課 | 時脈 6 天、GPIO 15 天、SysTick 已 9 天 |
| 學習頻率 | 未定義 | 29 天中有 18 天學習，每次多為 60～110 分鐘 |

- 照目前速度（技術課題約 10 天一課），剩下 25 課會到 **2027 年年中**，原訂 12-09 已不可能。
- 這不是偷懶造成的：18 個學習日、164 則筆記、約 9 萬字，投入很穩定。問題在**計畫把「每晚 1.5 小時」排成「一週 5 課」**，以及每課的深度沒有上限。
- App 目前完全看不出落後：週次日期是寫死的字串，提示詞還在告訴 Claude「預定 10-15～10-21」。

### 1.2 時間花在哪裡

| 觀察 | 數據 |
|---|---|
| 每課筆記量很大 | 時脈 65 則、GPIO 49 則、SysTick 45 則，每課約 3 萬字 |
| 筆記是一則一則手動貼的 | 164 則中有 107 則和前一則相隔不到 2 分鐘（連續貼上） |
| 延伸主題沒有上限 | SysTick 一課另外學了 GCC 最佳化等級、`_Static_assert`、enum、weak 符號、ST 文件編號等 |
| 提示詞要求每一步都做四點說明＋HAL 對照＋引導問題 | 每一步的固定成本高 |

這些內容本身有價值，但目前沒有界定每課「一定要學會什麼」，也沒有把延伸主題先記下來、之後再學的機制。

### 1.3 App 與提示詞的具體問題

| 編號 | 問題 | 證據 |
|---|---|---|
| P1 | 「問題」的已解決勾選形同虛設 | 50 則問題中 49 則是「未解決」，但內容其實都附了原因和解法；`QUESTIONS.md` 的未解決清單因此有 63 KB |
| P2 | 接續用的提示詞過長 | SysTick 的開始提示詞 16,550 字，其中 11,000 字是把「未解決問題」和最近 6 則筆記全文貼回去；求助提示詞 29,822 字 |
| P3 | TODO 會遺失 | 時脈課留下「做完 SysTick 後，把 timeout 改成以時間判斷」，但提示詞只帶「上一課」的 TODO，SysTick 課的上一課是 GPIO，所以沒被帶到；`clock_init.c` 現在仍用迴圈次數 |
| P4 | 收尾總整理沒有被執行 | 三堂已完成的課都沒有「總整理」筆記；課題的「總結」欄位全部是空的 |
| P5 | 重複與類型錯誤的筆記 | 5 組重複筆記；3 則標題寫【解法】卻存成問題或筆記；筆記無法編輯，只能刪掉重貼 |
| P6 | 提示詞對非暫存器課題不適用 | 「先問我要查 RM0008 哪一章」會套用到履歷、面試、分層架構、SPI Flash（看的是元件 datasheet）等課題 |
| P7 | 規則分散在三處且互相矛盾 | `app.py`、`CLAUDE.md`、專案說明各有一份；`CLAUDE.md` 同時寫了「逐行對照差異」和「不要直接說出答案」 |
| P8 | 提示詞仍引用舊 HAL 課程 | 每次都帶「對應的舊 HAL 版任務：W01-S05, W02-S03」；W02-S05 的內容是「把原本 HAL 版 ring buffer 接過來」。這和「舊 HAL 課的內容已經忘了，每個主題從頭設計」的要求衝突 |
| P9 | 進行紀錄不準 | 26 次進行中有 6 次開著過夜（超過 10 小時）；「本次進度」只填過 1 次，接續提示詞因此沒有「上次做到哪」 |
| P10 | 同步衝突沒有處理 | `git pull --rebase` 失敗時只顯示一行提示，repo 會停在 rebase 中途，之後的自動 commit 會出問題。目前 27 次啟動都沒發生，但兩台電腦輪流用遲早會遇到 |
| P11 | App 改壞會被自動推上 GitHub | 10-15 的空白畫面就是語法錯誤被自動 commit；目前沒有任何自我檢查 |
| P12 | 沒有複習機制 | 「複習」分頁只有搜尋和篩選；筆記照目前速度會超過 1,000 則，面試前無法重看 |
| P13 | `CLAUDE.md` 資訊過期 | 衝刺日期、邏輯分析儀規格、參考文件位置、「每完成一項任務請更新目前進度一節」都和現況不符 |

### 1.4 做得好的地方（不要動）

- 只用 Python 標準函式庫、單一資料檔、Git 當備份，架構簡單可靠。
- exe 啟動、獨立視窗、關閉自動結束都運作正常，紀錄中沒有任何錯誤。
- 筆記品質很高，【問題】幾乎都寫了錯在哪、為什麼、怎麼防止，這是面試最好的素材。
- 程式碼按課題分資料夾，每課可獨立編譯。

### 2.1 新舊 App 並行（2026-11-12 追加）

使用者希望保留舊版 App，以免新版用起來不順手。做法：

- 舊版 `tracker/` 與 `STM32Tracker.exe` **完全不動**。所有改進都做在 `tracker2/`，啟動檔是 `STM32Tracker2.exe`（綠色圖示）。
- 兩個 App 共用 `learning/progress.json`。新版遵守：
  - 只新增欄位，不改名、不刪除舊版在用的欄位。
  - 舊版新增的筆記沒有的欄位（例如之後的筆記 ID），新版讀取時自動補上。
  - 課題狀態只使用舊版認得的五種（未開始、進行中、已完成、卡關、暫緩）；合併、選修等資訊放在新欄位。
- 兩個 App 不能同時開啟，新版啟動時會檢查舊版是否開著。
- 自動產生的 `learning/*.md` 以最後存檔的那個 App 的格式為準。第 1 批沒有改格式；第 2 批改 `QUESTIONS.md` 之後，兩邊輪流用會讓格式來回變動，內容不會遺失。
- 新版順利使用 2～3 課之後，再由使用者決定是否移除舊版。

### 決定 1 對時程的影響

- 不訂次數之後，完成日不能事先承諾，改由 App 依實際速度推算並每天更新（見 3.3）。
- 第 3 批完成後由 App 計算：2026-11-12 的預估是 **2027-05-06**（平均每課 10.5 天 × 剩 16.7 課）。這比當初估的「4 月下旬」晚兩週，原因是加了準備項目，而且平均值改成只看時脈和 GPIO 兩課。
- 如果批次貼上和範圍控制能把每課縮到約 7 天，會是 2027 年 3 月上旬。
- 這些日期都是估計，App 會隨實際速度更新。求職線並行，所以履歷和複習不用等技術主線結束。

## 3. App 與提示詞的改進設計

### 3.1 提示詞重新設計

**(a) 規則只留一份**
- 新增 `tracker2/prompts/` 資料夾，規則寫成 Markdown 檔，`app.py` 讀檔組合，不再把規則寫死在 Python 字串裡。
- 之後要調整教法，只改 md 檔，不會再動到程式。
- `CLAUDE.md` 的「教學方式」一節改成由同一份規則產生，並刪掉互相矛盾的句子。
- 專案說明（claude.ai 專案裡的文件）App 寫不到，改規則後由 Claude 同步一次；提示詞本身自帶完整規則，所以專案說明只需要放背景資料。

**(b) 依課題類型套用不同規則**（`progress.json` 每課加 `kind` 欄位）

| 類型 | 適用課題 | 規則重點 |
|---|---|---|
| register | RCC、GPIO、SysTick、EXTI、TIM 與 PWM、USART、DMA、I²C、SPI、IWDG 與低功耗 | 現有的「為什麼／設了什麼／代表什麼／順序」四點與暫存器表格 |
| driver | 陀螺儀、SPI Flash、螢幕 | 先讀元件 datasheet 的 register map 或指令表與時序圖；表格改為「指令或暫存器｜值｜意義｜出處」；用邏輯分析儀驗證波形 |
| arch | CLI、分層、錯誤碼、整合 | 先設計介面（.h）與相依方向，再實作；驗收看「誰可以呼叫誰」 |
| debug | Startup／Linker、HardFault | 觀察 → 假設 → 驗證；工具操作步驟寫清楚 |
| career | 履歷、作品整理、題庫、模擬面試 | Claude 扮演審稿人或面試官；不套用任何暫存器規則 |

**(c) 三種提示詞，各有長度上限**

| 提示詞 | 使用時機 | 內容 | 上限 |
|---|---|---|---|
| 新課題 | 第一次開始一課 | 課題資訊、已有的模組介面、未處理的 TODO、上一課筆記標題、規則 | 約 6,000 字 |
| 接續（新對話） | 同一課換一個新對話 | 課題資訊、最新一則【本次進度】、本課筆記**標題**、真正待解決的問題、規則 | 約 6,000 字 |
| 求助 | 卡關 | 卡在哪、相關程式碼、本課筆記標題、精簡規則 | 規則約 3,000 字＋程式碼 |

- 筆記全文不再貼回提示詞，只貼標題。這一項就能把 SysTick 的提示詞從 16,550 字降到約 6,000 字。
- 同一個對話隔天繼續時不需要再貼提示詞，App 的按鈕說明要寫清楚。

**(d) 新增或修改的內容**
- **必學範圍**：每課帶入一份必學項目（見 4.5）。範圍內的要教到我能不看筆記口頭解釋，不限次數。
- **範圍控制**：課堂中冒出的主題依 4.3 分成「必學／相關基礎／延伸」三類處理；延伸主題用一兩句話回答後記成【待學】，不展開。App 另外列出待學清單。
- **HAL 對照**：每課挑 1～2 個差異最大的地方，貼出 HAL 片段並給引導問題；其餘留到收尾總整理一次並排比較。
- **已有的模組介面**：自動從上一課專案的 `Inc/*.h` 擷取函式宣告（例如 `Clock_Init()`、`BSP_SysTick_GetTick()`），讓 Claude 知道可以直接用什麼。
- **全域 TODO**：所有課題筆記裡的 TODO 行都持續帶入，直到在 App 勾掉。
- **本次進度交接**：你說「今天到這」時，Claude 產生一則【本次進度】（完成了哪些、下一步、還沒弄懂的），貼進 App 後成為下次接續的起點。
- **移除**：「對應的舊 HAL 版任務」、寫死的預定日期、「4.5」這種插入的編號。
- **補上**：我讀的是中文版 RM0008，請用節號和暫存器名稱，不要用頁碼。

### 3.2 筆記流程

| 項目 | 設計 |
|---|---|
| 批次貼上 | 把 Claude 整段回覆貼進一個框，App 依 ```` ```markdown ```` 區塊或【筆記】【問題】【解法】【本次進度】【待學】開頭自動拆成多則，顯示預覽後一次存入 |
| 類型自動判斷 | 依第一行的【】前綴決定類型，不用手動切換 |
| 重複偵測 | 同一課已有相同標題時，預覽中標示並讓你選擇「取代」或「略過」 |
| 編輯筆記 | 每則加「編輯」按鈕（後端已支援，前端沒做） |
| 筆記編號 | 每則加固定 ID，取代現在用「第幾則」定位的做法（編輯、刪除、兩台電腦同步都更安全） |
| 一次性資料整理 | 刪除 5 組重複、修正 3 則類型錯誤、依決定 3 處理 49 則問題 |

### 3.3 進度與時程

- **資料欄位**：每課加 `priority`（core／optional／merged）、`kind`、`order`、`must`（必學範圍）、`optional_topics`。
- **不訂每課次數**。每課顯示的是「必學範圍已完成 k／n 項」和「已用 d 個學習日」，只供參考，不設上限、不變色警告。
- **必學範圍檢查清單**：每課的必學項目可以在 App 逐項勾選；提示詞帶入尚未勾選的項目。
- **日期改為動態**：不再寫死「10-15～10-21」。預估完成日 ＝ 今天 ＋ 剩餘必修課數 × 最近 3 堂已完成技術課的平均天數，每次開 App 重新計算。
- **頂端儀表**：顯示「必修完成 x／y」、「最近 4 週有 n 個學習日」、「預估技術主線完成日」。
- **進行紀錄**：
  - App 關閉時如果還有課題進行中，自動結束這次（時間記到最後一次操作），並做一次自動儲存。
  - 「結束本次課題」的未完成選項，欄位改成兩格：「做到哪」「下次從哪開始」。
- **完成檢查**：按「已完成」時顯示檢查清單（必學範圍逐項、完成標準逐條、總整理筆記已存、程式碼已上傳、本課 TODO 已處理或延後）。缺項只提醒，不擋。

### 3.4 複習與面試準備

- **複習測驗提示詞**：每完成一課，App 提示做一次約 15 分鐘的口頭複習；已完成的課題也多一顆「複習」按鈕，產生提示詞讓 Claude 依必學範圍、完成標準和你踩過的錯出 5～8 題口頭題，你不看筆記回答，Claude 評分並指出要重看的筆記標題。
- **複習紀錄**：記下每次複習日期與結果；間隔 1、3、7、21 天提醒，任務列表顯示「待複習」。
- **面試卡**：收尾總整理的「面試版 30 秒說明」和驗收回答，自動彙整成 `learning/INTERVIEW.md`，依主題排列。
- **`QUESTIONS.md` 改版**：改成依課題列出「踩過的錯」標題清單，連到筆記頁；只有真正待解決的問題放最上面。
- **補做總整理**：為時脈、GPIO、SysTick 三課各產生一份「補做總整理」提示詞。

### 3.5 穩定性

| 項目 | 設計 |
|---|---|
| 同步衝突 | pull 失敗時自動 `git rebase --abort` 還原，畫面顯示固定的警告條和處理步驟，並暫停自動 commit 直到解決 |
| 自我檢查 | 新增 `tracker2/selftest.py`：檢查 Python 語法、頁面 JavaScript 語法、用目前資料產生三種提示詞、跑 Markdown 表格測試。改完 App 一定要跑 |
| 啟動防呆 | App 啟動時先做語法層級的檢查；頁面載入失敗時顯示錯誤訊息，不要再出現空白畫面 |
| 同步範圍 | `stage_all` 加入 `docs/` |
| 文件 | 更新 `README.md`、`CLAUDE.md`（邏輯分析儀改為 Kingst LA1010、參考文件位置改為桌面的「STM32 參考文件」、註明讀中文版 RM0008） |
| 舊 HAL 計畫 | 封存為唯讀分頁，資料保留，不再產生提示詞 |

### 3.6 不建議做的事

- 不改用資料庫或前端框架：目前規模用不到，還會增加兩台電腦同步的難度。
- 不把 `progress.json` 拆成多個檔：加上筆記 ID 和衝突處理後已經足夠。
- 不恢復計時器，也不訂每課次數：用學習日數和實際完成速度估時程就夠了。

## 4. 課程重排（已依決定 1、2 調整）

### 4.1 原則

- 課題代碼不變（Git tag 和資料夾都用它）。
- 面試常問、或作品一定用到的內容放必修；其餘放選修，必修做完後再挑。
- 每課有一份「必學範圍」。範圍內的要學到能不看筆記口頭解釋，花幾次都可以；範圍外的依 4.3 的規則處理。
- 選修不計入進度百分比。

### 4.2 和上一版草案的差異

| 項目 | 上一版 | 這一版 | 理由 |
|---|---|---|---|
| W02-S03 PWM | 整課選修 | **基礎併入 W02-S02 Timer（必修）**；進階留選修 | 「PWM 的頻率和 duty 怎麼算、怎麼產生」是常見面試題，而且和 Timer 共用同一組暫存器 |
| 低功耗模式 | 沒有 | **併入 W06-S01（必修）** | Sleep／Stop／Standby 的差異與喚醒是 MCU 與 IC 設計公司的常見題目，原計畫完全沒有 |
| ISR 與主程式共享資料 | 沒有明列 | **列入 W02-S01 必學範圍** | 競爭條件與臨界區是面試高頻題 |
| C 手寫題 | 沒有明列 | **列入 W08-S01** | 白板題（`memcpy`、位元反轉、鏈結串列）在台灣韌體面試很常見 |

合併後的課題在 App 裡保留原代碼，狀態標示為「已併入某課」，不會消失。

### 4.3 範圍控制規則（取代每課次數上限）

Claude 遇到課堂中冒出的主題時，依下面三類處理：

- 【待學】會集中列在 App 裡，之後有零碎時間可以挑來學。

### 4.5 各課必學範圍

實作時寫入 `progress.json` 的 `must` 欄位，App 顯示成檢查清單，提示詞也會帶入。

**W01-S04 SysTick 與 non-blocking（收尾）**
- 完成驗收與收尾總整理。
- 處理時脈課留下的 TODO 是否在本課做，或延到 W03-S02（建議延後，那一課會統一處理 timeout）。

**W01-S05 Startup 與 Linker Script**
- 向量表的前兩項（初始 SP、`Reset_Handler`）與 BOOT 腳位的關係。
- `Reset_Handler` 做的事：複製 `.data`、清 `.bss`、進入 `main()`。
- `.text`、`.rodata`、`.data`、`.bss`、heap、stack 各放在 Flash 或 RAM 的哪裡。
- 讀 `.ld` 的 `MEMORY` 與 `SECTIONS`；從 `.map` 找出變數位址與 Flash／RAM 用量。
- 有初值的全域變數、`const`、`static` 區域變數、一般區域變數分別放在哪裡。
- stack overflow 會發生什麼事。
- 面試：3 分鐘口述「上電到 main」。

**W02-S01 EXTI + NVIC**
- `AFIO_EXTICR` 選腳位；`EXTI_IMR`、`RTSR`、`FTSR`；`PR` 寫 1 清除，以及為什麼不能用讀改寫。
- NVIC：致能、優先權分組、搶佔優先權與子優先權。
- 向量表和 handler 名稱的對應。
- ISR 該做與不該做的事。
- ISR 與主迴圈共享變數：`volatile`、臨界區（暫時關中斷）、非原子操作造成的競爭。
- 中斷延遲與巢狀中斷的概念。
- 按鍵用 EXTI 和用輪詢去彈跳的比較。

**W02-S02 Timer 週期中斷＋PWM 基礎**
- 計時器的時脈來源：APB1 分頻不是 1 時，TIM 時脈為什麼是 PCLK1 的 2 倍。
- `PSC`、`ARR` 的計算（為什麼都要減 1）、更新事件、`UIF` 的清除。
- 用邏輯分析儀驗證週期。
- PWM：`CCMR` 的 PWM mode 1、`CCER`、`CCR` 與 duty、頻率計算；腳位設成複用推挽輸出。
- SysTick 和通用計時器的差異，各自適合做什麼。
- 選修：preload（`ARPE`、`OCxPE`）、輸入捕捉。

**W02-S04 USART 暫存器驅動**
- 資料幀格式（起始、資料、同位、停止）；`BRR` 計算與鮑率誤差。
- `TXE` 與 `TC` 的差異；`RXNE`；`ORE`、`FE`、`NE` 錯誤旗標與清除順序。
- 中斷接收加 ring buffer：head／tail 的設計、滿與空的判斷、哪些變數要 `volatile`。
- 輪詢、中斷、DMA 三種收發方式的取捨。
- 把 `printf` 接到 UART。
- 用邏輯分析儀解碼驗證。

**W02-S05 CLI（從頭寫）**
- 行緩衝與字元處理（退格、CR／LF）。
- 把字串切成 `argc`／`argv`，不用動態配置。
- 函式指標命令表：新增指令只加一行。
- 輸入驗證與錯誤回報（超長、未知指令、參數錯誤）。
- 模組介面：CLI 不直接碰 UART 暫存器。

**W03-S01 DMA（USART TX）**
- DMA 解決什麼問題；從 RM0008 找出周邊對應的 DMA 通道。
- `CPAR`、`CMAR`、`CNDTR`、`CCR`：方向、位址遞增、資料寬度、循環模式。
- 啟動順序、傳輸完成中斷、旗標清除。
- 周邊端的 DMA 致能位（`USART_CR3` 的 `DMAT`）。
- 傳送期間緩衝區必須一直有效（不能用區域變數）。
- DMA 和中斷方式的比較。
- 選修：ADC1 連續轉換＋DMA 循環模式。

**W03-S02 分層＋錯誤碼＋timeout**
- `bsp`、`drivers`、`app`、`common` 的相依方向；`drivers` 裡不出現暫存器名稱。
- 介面設計：`.h` 只放呼叫者需要的東西。
- 統一錯誤碼 `err_t` 與回傳慣例。
- 用 tick 計時的 timeout，處理時脈課留下的 TODO；32-bit 溢位時仍正確的比較寫法。
- 換 MCU 時要改哪一層。

**W04-S01 軟體 I²C**
- 為什麼用開漏加上拉；上拉電阻和速度的關係。
- START、STOP、重複起始；位址加讀寫位元；ACK 與 NACK 各由誰送。
- 時序規則：SCL 為高時 SDA 必須穩定。
- clock stretching；匯流排卡死的原因。
- 用邏輯分析儀做 I²C 解碼。
- I²C、SPI、UART 的比較。

**W04-S02 陀螺儀驅動**
- 讀元件 datasheet 的 register map；用 `WHO_AM_I` 驗證通訊。
- 初始化序列的每一項理由（解除睡眠、量程、取樣率、濾波）。
- 多 byte 連續讀取；高低位元組的順序與有號數的組合。
- 原始值換算成物理量；靜止零點校正。
- 驅動只依賴 I²C 介面，裝置不回應時回傳錯誤碼。
- 完成後：寫履歷第一版。

**W04-S03 硬體 I²C**
- `CR1`、`CR2`、`CCR`、`TRISE` 的計算。
- 事件順序：`SB`、`ADDR`（先讀 `SR1` 再讀 `SR2` 清除）、`TXE`、`BTF`、`RXNE`。
- 讀 1 byte、2 byte、多 byte 的流程差異。
- `AF`、`BERR`、`ARLO` 的錯誤處理與 timeout。
- 匯流排卡死時送 9 個 clock 復原。
- 同一個陀螺儀驅動只換底層就能運作。

**W05-S01 SPI 暫存器驅動**
- 四條線的角色；全雙工移位的原理（為什麼送一個 byte 才收得到一個 byte）。
- `CPOL`、`CPHA` 四種模式與時序圖。
- `CR1`：主從、鮑率分頻、`SSM`／`SSI`、位元順序。
- `TXE`、`RXNE`、`BSY` 的使用時機。
- CS 用 GPIO 控制的時機。
- 用邏輯分析儀做 SPI 解碼。

**W05-S02 SPI Flash 驅動**
- JEDEC ID；指令格式（指令、位址、資料）。
- 寫入前為什麼要抹除（位元只能從 1 變 0）；Sector 與 Page 的大小。
- Write Enable、狀態暫存器的 BUSY、Page Program 與跨頁處理。
- 抹寫壽命的概念。
- 寫入後讀回驗證。

**W05-S03 SPI 螢幕＋共用匯流排**
- 讀控制 IC datasheet 的初始化序列；指令與資料的區分方式。
- 畫面緩衝區與更新方式；用點陣字型顯示字元與數字。
- 兩個裝置共用一組 SPI：各自的 CS、切換時的模式與速度。
- 選修：用 DMA 刷新整頁並量測時間。

**W06-S01 IWDG＋Reset 原因＋低功耗模式**
- IWDG 的時脈來源（LSI）；`KR`、`PR`、`RLR` 與逾時時間的計算；餵狗位置的設計。
- IWDG 和 WWDG 的差異。
- 讀 `RCC_CSR` 判斷重置來源並清除旗標。
- Sleep、Stop、Standby 的差異、各自的喚醒來源、喚醒後的時脈狀態。
- 實作：用 `WFI` 進入 Sleep，由中斷喚醒。
- 選修：Stop 模式與喚醒後重新設定時脈。

**W06-S02 HardFault 除錯**
- 進入例外時自動存入堆疊的暫存器。
- 從堆疊裡的 PC 與 LR 找出出錯位置（用 `.map` 或 `addr2line`）。
- `CFSR`、`HFSR`、`BFAR` 的判讀。
- 常見原因：空指標、陣列越界、stack overflow、除以零。
- 寫一個可重複使用的 fault handler。

**W06-S03 姿態記錄器整合**
- 資料流：TIM 定時取樣 → 螢幕顯示 → 寫入 Flash。
- 記錄格式：header、序號、CRC。
- CLI 指令：`log start`、`log stop`、`log dump`、`log erase`、`status`。
- 斷電後資料仍在；連續記錄 5 分鐘不當機。
- 打上 Git tag v1.0。

## 6. 執行者注意事項

這些是前幾次修改 App 時實際踩到的問題。

**環境**
- repo 在使用者電腦的 `C:\Users\user\Desktop\STM32-Learning-Portfolio`，透過連結的電腦存取；shell 裡的路徑是 `$HOME/mnt/STM32-Learning-Portfolio`。
- 那個 shell 是 Linux 環境，不能執行 exe，但可以執行 `python3 -B tracker2/selftest.py`，也有 `node` 可以做語法檢查。要實際啟動 App 測試時，先把 `tracker2/` 和 `learning/` 複製到 `$HOME` 底下再跑（或設定 `STM32_TRACKER_ROOT`），因為那個環境不能在 repo 裡刪除或取代檔案，App 存檔會失敗。執行 Python 時加 `-B`，避免在 repo 裡留下 `__pycache__`。
- 需要看畫面時，把檔案複製到雲端工作區，用 Playwright 加 Chromium 截圖。

**修改檔案**
- 一律在 shell 裡用 Python「讀取 → 取代 → 寫回」原地修改，取代前用 `assert` 確認目標字串只出現一次。
- 不要用「在雲端改好再整檔寫回」的方式：這個方式曾經兩次把舊內容寫回去。如果非用不可，寫回後一定要用 `sha1sum` 比對。
- 改 `index.html` 的 JavaScript 字串時注意反引號：頁面大量使用樣板字串，內容裡的反引號必須跳脫（10-15 的空白畫面就是這個原因）。

**Git**
- 不要在那個 shell 裡執行 `git commit`、`git stash`、`git checkout`、`git pull`：該環境預設不能刪檔，Git 會留下 lock 檔，讓 App 之後的 Git 操作失敗。唯讀指令（`log`、`status`、`diff`、`show`）可以用。
- 那個 shell 連不到 GitHub。commit 與 push 交給 App：下次啟動或結束課題時會自動處理。

**資料**
- 修改 `learning/progress.json` 前先確認兩個 App 都已關閉（`tracker/.app_port` 和 `tracker2/.app_port` 都不存在），並先複製一份備份到 `$HOME`。
- 資料轉換寫成可重複執行的腳本，轉換後檢查課題數（第 3 批之後是 75）與筆記數是否符合預期。
- `learning/README.md`、`learning/QUESTIONS.md`、`learning/INTERVIEW.md`、`learning/notes/` 由 App 產生，不要手動改；改 `export_markdown()`。
- 掛載的資料夾不能取代或刪除檔案，所以 App 的 `save()`（用 `os.replace`）在那個 shell 裡會失敗。要改資料時用 `open(..., "w")` 原地寫入，再呼叫 `export_markdown()`；執行時加上 `TZ=Asia/Taipei`，產生的時間才會是台灣時間。

**教學規則（改提示詞時要保留）**
- 不用 ①②③、「步驟 2」指涉前文，一律寫出內容。
- 每一步說明為什麼、設了什麼、代表什麼、為什麼是這個順序；收尾時從頭到尾再講一次。
- HAL 對照：直接貼 HAL 關鍵片段，給引導問題，不直接說答案；每課 1～2 個重點，其餘在收尾並排比較。
- 不訂每課的次數上限；用必學範圍和「必學／相關基礎／延伸」三類規則控制範圍，必學的內容一定要學到。
- 不引用舊 HAL 課程的內容。
- 筆記先整理完，再進下一步實作。
- 設定值等學習者查完再對答案。
- 回覆一律使用繁體中文。
