### [筆記] 2026-07-01 00:00

SCL = Serial Clock
SDA = Serial Data
SCL → 主要由 Master 產生時脈
SDA ↔ 雙向傳資料

I²C 的 SDA / SCL 不是一般 Push-Pull 輸出，而是 Open-Drain。
這代表裝置通常只會主動做兩件事：
拉低 → 0
放開 → 由 Pull-up resistor 拉成 1
不會像一般 GPIO 那樣主動輸出 High。

Open-Drain 輸出只有兩種動作：
1. 拉低
   SDA ──→ GND
   結果 = 0
2. 放開
   SDA 不主動輸出電壓
   交給 Pull-up 拉高
   結果 = 1

為什麼 I²C 不直接用 Push-Pull？
因為 SDA 是多個裝置共用的一條線。
假設用 Push-Pull：
STM32 主動輸出 3.3V
MPU6050 同時主動輸出 0V
就會形成輸出打架，甚至可能產生很大的電流。
但 Open-Drain 不會有「有人硬推 High」：
STM32 放開
MPU6050 拉低
→ SDA = 0
所以 I²C 可以讓多個裝置安全共用 SDA。

Open-Drain：只能主動拉 Low；High 是靠 Pull-up 得到的。

只要總線上任何一個裝置拉 Low，整條 SDA 就會是 Low。
可以記成：
沒有人拉低 → Pull-up 拉成 1
有人拉低   → 變成 0

I²C 在閒置時通常：
SCL = 1
SDA = 1
當 SCL 維持 High 時：
SDA：1 → 0
這代表 START。
而：
SDA：0 → 1
則代表 STOP。

I²C idle：
SCL = 1
SDA = 1
START：
SCL 保持 1
SDA：1 → 0
STOP：
SCL 保持 1
SDA：0 → 1

START 之後，Master 通常第一個送的是：
7-bit Slave Address + 1-bit R/W
MPU-6050 常見 7-bit address 是：
0x68
如果 AD0 = 0。
真正送到 I²C Bus 上的第一個 Byte 是：
[ 7-bit Address ][ R/W ]

R/W = 0 → Write
R/W = 1 → Read

用 HAL 很容易踩到的點：
在 STM32 HAL 裡，很多 I²C API 的 DevAddress 參數要傳的是已經左移 1 bit 的位址。
也就是 MPU-6050 常會寫成：
#define MPU6050_ADDR (0x68U << 1)
這樣 MPU6050_ADDR 就是：
0xD0
之後，會多出第 9 個 Clock。
這第 9 個 Clock 不是資料 bit，而是讓 Slave 回：
ACK / NACK

ACK  = Slave 在第 9 個 Clock 主動把 SDA 拉低
NACK = Slave 不拉低 SDA，讓 Pull-up 維持 High
所以你可以把 ACK 想成：
Slave 說：「這個 Address 是我的，我有收到。」
流程會像：
START
→ 0xD0
→ 第 9 個 Clock
→ MPU-6050 拉低 SDA
→ ACK
如果地址錯了，例如 Master 送到不存在的 Slave：
START
→ Address
→ 第 9 個 Clock
→ 沒有人拉低 SDA
→ SDA 被 Pull-up 拉成 High
→ NACK

第 1 層：I²C Slave Address
0x68
→ 找到「哪一顆裝置」
第 2 層：Register Address
例如 WHO_AM_I
→ 找到「這顆裝置裡面的哪個暫存器」
所以一筆典型的寫入會長得像：
START
→ Slave Address + Write
→ ACK
→ Register Address
→ ACK
→ Data
→ ACK
→ STOP

假設我們要讀 MPU-6050 的 WHO_AM_I。
Master 必須先告訴 MPU-6050：
「我等等要讀的是 WHO_AM_I 這個 Register。」
所以通常流程不是一開始就直接 Read，而是：
先 Write Register Address
再 Read Register Data

之後看 Datasheet 會遇到的細節：很多 I²C 裝置內部其實有一個 Register Pointer，所以如果直接 Read，它可能會從「目前 Pointer 指到的位置」開始讀，而不是完全不知道要讀什麼。
因此要可靠地指定某一個 Register，典型做法仍然是：
START
→ Slave Address + Write
→ ACK
→ Register Address
→ ACK
→ ...
這時 MPU-6050 內部就知道：
Register Pointer = 我們指定的 Register
接下來我們不是立刻 STOP 再重新開始，而常會看到一個非常重要的 I²C 動作：
Repeated START
流程會變成：
START
→ Slave Address + Write
→ ACK
→ Register Address
→ ACK
→ Repeated START
→ Slave Address + Read
→ ACK
→ Data
→ ...

一般重新開始一筆交易：
START
→ ...
→ STOP
→ START
→ ...
Repeated START：
START
→ ...
→ Repeated START
→ ...
→ STOP
Repeated START 的意義是：
Master 還沒有把這次 Bus Transaction 結束，而是在同一筆交易中切換方向或切換操作。
這對「先指定 Register，再讀資料」很常見。
例如讀 MPU-6050 某個 Register：
START
→ 0xD0          // Slave Address + Write
→ ACK
→ Register Addr
→ ACK
→ Repeated START
→ 0xD1          // Slave Address + Read
→ ACK
→ Data
→ NACK
→ STOP

前面 Address / Register Address 階段：
Master 傳
Slave 回 ACK/NACK
進入 Read Data 階段：
Slave 傳 Data
Master 回 ACK/NACK
如果 Master 還想繼續讀下一個 Byte，就回：
ACK
意思是：
我還要，請繼續送。
如果 Master 已經讀到最後一個 Byte，就回：
NACK
意思是：
這是最後一個，不要再送了。
所以讀 1 Byte 的完整流程可以先記成：
START
→ Slave Address + Write
→ ACK
→ Register Address
→ ACK
→ Repeated START
→ Slave Address + Read
→ ACK
→ Data
→ NACK
→ STOP

關鍵不是「ACK 永遠由 Slave 回」，而是看現在是誰在接收資料：
誰接收 Byte
→ 誰負責在第 9 個 Clock 回 ACK / NACK
所以：
Master 傳 Address / Register
→ Slave 接收
→ Slave 回 ACK/NACK
Slave 傳 Data
→ Master 接收
→ Master 回 ACK/NACK

START
→ 0xD0        Master 送
→ ACK         Slave 回
→ 0x75        Master 送
→ ACK         Slave 回
→ Repeated START
→ 0xD1        Master 送
→ ACK         Slave 回
→ 0x68        Slave 送   ← WHO_AM_I Data
→ NACK        Master 回
→ STOP        Master

STM32                    MPU-6050
Master                    Slave
PB6 / SCL  ------------> SCL
PB7 / SDA  <-----------> SDA
3.3V      -------------> VCC
GND       -------------- GND
GND       -------------- AD0

訪問前須先喚醒 MPU 6050
#define MPU6050_I2C_ADDRESS (0x68U << 1)
#define MPU6050_WHO_AM_I_REG 0x75
#define MPU6050_PWR_MGMT_1_REG 0x6B
void wake_up(void){

        HAL_I2C_Mem_Write(
            &hi2c1,   // I2C
            MPU6050_I2C_ADDRESS,   // Slave
            MPU6050_PWR_MGMT_1_REG,   // Register
            I2C_MEMADD_SIZE_8BIT,   // Register address size

            100U// Timeout
        );
}

MPU-6050 的加速度資料從 ACCEL_XOUT_H 開始，X/Y/Z 三軸各 16-bit，一共 6 Bytes。
#define MPU6050_ACCEL_XOUT_H_REG    0x3BU
static uint8_t accel_raw_buffer[6] = {0};
為什麼是 6？
X軸 → High + Low = 2 Bytes
Y軸 → High + Low = 2 Bytes
Z軸 → High + Low = 2 Bytes
總共 = 6 Bytes
這一次我們不需要分別讀：
0x3B
0x3C
0x3D
0x3E
0x3F
0x40
而是利用 I²C Register 的連續讀取：
從 0x3B 開始
↓
一次讀 6 Bytes
↓
buffer[0] ~ buffer[5]
這就是 Burst Read。

HAL_I2C_Mem_Read(
    &hi2c1,
    MPU6050_I2C_ADDRESS,
    MPU6050_ACCEL_XOUT_H_REG,
    I2C_MEMADD_SIZE_8BIT,
    accel_raw_buffer,
    6U,
    100U
);
不用寫 &accel_raw_buffer。因為陣列名稱 accel_raw_buffer 傳進函式時，本身就會轉成指向第一個元素的指標，相當於：
&accel_raw_buffer[0]
所以 HAL 會依序把 6 Bytes 寫進：
buffer[0] ← 0x3B  ACCEL_XOUT_H
buffer[1] ← 0x3C  ACCEL_XOUT_L
buffer[2] ← 0x3D  ACCEL_YOUT_H
buffer[3] ← 0x3E  ACCEL_YOUT_L
buffer[4] ← 0x3F  ACCEL_ZOUT_H
buffer[5] ← 0x40  ACCEL_ZOUT_L

MPU-6050 很重要的一個觀念：每一軸不是 8-bit，而是 signed 16-bit。
例如 X 軸：
High Byte = buffer[0] = 0x03
Low  Byte = buffer[1] = 0x74
要組成：
0x03 74
   ↓
0x0374
做法不是相加：
high + low 
而是：
High Byte 左移 8 bit
        ↓
XXXX XXXX 0000 0000
        ↓
再把 Low Byte 放進低 8 bit

加速度可能是負值，因此最後變數不能使用：
uint16_t
而要用：
int16_t

accel_x_raw =
    (int16_t)(((uint16_t)accel_raw_buffer[0] << 8U)
              | (uint16_t)accel_raw_buffer[1]);
accel_y_raw =
    (int16_t)(((uint16_t)accel_raw_buffer[2] << 8U)
              | (uint16_t)accel_raw_buffer[3]);
accel_z_raw =
    (int16_t)(((uint16_t)accel_raw_buffer[4] << 8U)
              | (uint16_t)accel_raw_buffer[5]);
比原本：
(int16_t)((accel_raw_buffer[0] << 8) | accel_raw_buffer[1])
更嚴謹

要確認目前 MPU-6050 是 ±2g / ±4g / ±8g / ±16g，最直接的方法是：讀 ACCEL_CONFIG 暫存器。
MPU-6050 支援這四種加速度量測範圍。
先知道要看哪個 Register
ACCEL_CONFIG 的位址是：
#define MPU6050_ACCEL_CONFIG_REG    0x1CU
這個 Register 裡面，我們關心的是：
bit 4:3 = AFS_SEL
也就是只看這兩個 bit：
AFS_SEL = 00 → ±2g
AFS_SEL = 01 → ±4g
AFS_SEL = 10 → ±8g
AFS_SEL = 11 → ±16g
對應的 sensitivity 之後換算會用到：
±2g  → 16384 LSB/g
±4g  → 8192  LSB/g
±8g  → 4096  LSB/g
±16g → 2048  LSB/g
