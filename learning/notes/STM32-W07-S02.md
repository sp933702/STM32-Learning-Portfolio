## 問題與筆記

### [筆記] 2026-08-09 00:00

UART DMA 傳送：
CPU 準備字串
→ 啟動 UART TX DMA
→ DMA 將字串逐 Byte 搬到 USART1
→ CPU 繼續處理 PWM、UART RX、ADC 等工作
→ 傳送完成後進入回呼函式

UART Log 的資料來源是：uart_log_buffer[]
它位於 SRAM，屬於 Memory。
資料目的地是：USART1->DR
它是 USART1 的硬體暫存器，屬於 Peripheral。

Peripheral Increment = Disable
因為每個 Byte 都寫到固定的 UART 資料暫存器：
uart_log_buffer[0] → USART1->DR
uart_log_buffer[1] → USART1->DR
uart_log_buffer[2] → USART1->DR
Peripheral 位址始終不變。

UART 每次傳送的是一個 uint8_t：
uart_log_buffer[0] → 1 Byte
uart_log_buffer[1] → 1 Byte
uart_log_buffer[2] → 1 Byte
例如字串：ABC
DMA 會依序搬運：
'A' → USART1->DR
'B' → USART1->DR
'C' → USART1->DR

若選 Circular，DMA 傳完 log_length 個 Byte 後，會自動回到 Buffer 開頭，再把同一段字串重複傳送：
ABC\r\nABC\r\nABC\r\n……
而 UART Log 每次內容可能不同，所以應該是：
準備一段新 Log
→ DMA 傳送一次
→ 傳完停止
→ 等待下一段 Log

DMA1 Channel 4 global interrupt
→ 處理 USART1_TX DMA 搬運完成
USART1 global interrupt
→ 保留 UART RX 中斷，並處理 UART 最後一個位元真正送完的事件

__HAL_LINKDMA(huart, hdmatx, hdma_usart1_tx);
是本節的 UART TX DMA 連結：
huart1
→ hdmatx
→ hdma_usart1_tx
→ DMA1 Channel 4
資料方向：
uart_log_buffer[] → USART1->DR

UART TX DMA 的完成流程其實分成兩個階段：
DMA1 Channel 4 中斷 → 代表 DMA 已把最後一個 Byte 搬到 USART1->DR
USART1 中斷
→ 代表 UART 已把最後一個 Byte 的停止位真正送出 TX 腳
→ HAL 才將 UART 傳送狀態恢復為 Ready
→ 呼叫 UART TX 完成回呼
所以兩個中斷都需要保留：
DMA1_Channel4_IRQHandler()
USART1_IRQHandler()

void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART1)
    {
        uart_tx_dma_busy = 0U;
    }
}
流程會是：
UART TX DMA 開始
→ uart_tx_dma_busy = 1U
→ DMA 搬完資料
→ UART 最後一個 Byte 真正送完
→ HAL_UART_TxCpltCallback()
→ 確認是 USART1
→ uart_tx_dma_busy = 0U

假設 HAL_UART_Transmit_DMA() 回傳：
HAL_BUSY
或：
HAL_ERROR
代表 DMA 根本沒有成功開始。
這時候：
uart_tx_dma_busy 已經 = 1
但 DMA 沒有在傳
→ 不會出現 TX Complete Callback
→ busy 永遠不會被清回 0
之後所有週期 Log 都會被卡住。

if (uart_status != HAL_OK)
{
    uart_tx_dma_busy = 0U;
}
不需要 else。
原因是成功時：
HAL_OK
→ uart_tx_dma_busy 保持 1
→ DMA 背景傳送
→ HAL_UART_TxCpltCallback()
→ uart_tx_dma_busy = 0
失敗時：
HAL_BUSY / HAL_ERROR
→ 沒有成功開始這次 DMA
→ 不一定會有完成 Callback
→ 必須自己 uart_tx_dma_busy = 0

static volatile uint8_t uart_tx_dma_busy = 0U;
意義：
0U → UART TX DMA 空閒
1U → UART TX DMA 正在傳送
需要 volatile，因為：
main()                  → 讀 / 寫
UART TX Complete ISR    → 寫
變數會跨 Main Context 與 Interrupt Context 使用。

UART TX DMA 與原本 Command Response 共用：
USART1 TX
目前：
Periodic ADC Log
→ HAL_UART_Transmit_DMA()
Command Response
→ HAL_UART_Transmit()
例如：
HAL_UART_Transmit(&huart1,
                  (uint8_t *)uart_status_message,
                  sizeof(uart_status_message) - 1U,
                  100U);
若 DMA 正在使用 USART1：
ADC Log DMA 傳送中
→ status command 到達
→ Blocking HAL_UART_Transmit()
→ UART TX State Busy
→ 可能回傳 HAL_BUSY
而原本沒有檢查回傳值，因此 Command Response 可能直接消失

Command Response > Periodic Debug Log
理由：
Periodic ADC Log
→ 少一筆通常沒關係
Command Response
→ 使用者主動要求
→ 無回覆容易被認為指令失敗
但不是強制中止正在傳的 DMA。
而是：
DMA Log 已經開始
→ 讓它完成
→ 記錄 Command Pending
→ DMA 空閒後優先送 Command

static uint8_t uart_status_response_pending = 0U;
這個變數目前只在 main() 使用，所以不需要 volatile。
收到：
status
時：
if (uart_tx_dma_busy == 0U)
{
    HAL_UART_Transmit(...);
}
else
{
    uart_status_response_pending = 1U;
}
代表：
UART 空閒
→ 立即回覆
UART DMA 忙
→ 先記住 Pending

Pending 處理必須放在：
if ((current_time - uart_previous_time) >= UART_LOG_INTERVAL_MS)
之前。
Pending Command Response
        ↓
Periodic ADC Log
