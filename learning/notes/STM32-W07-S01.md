## 問題與筆記

### [筆記] 2026-08-06 00:00

可以把它理解成：
CPU：主管
DMA：搬運工
ADC：資料生產者
記憶體陣列：倉庫
沒有 DMA：
主管每生產一件貨，都要親自搬進倉庫
使用 DMA：
主管先交代搬運規則
搬運工自動把每件貨放進倉庫
全部完成後再通知主管

DMA 的主要優點
1. 減少 CPU 負擔
CPU 可以同時執行：
UART 命令解析
PWM 呼吸燈
按鍵事件
其他週期任務
2. 適合大量或連續資料
例如：
ADC 連續取樣
UART 接收大量資料
SPI 感測器資料
I²C 資料
音訊取樣
3. 降低遺漏資料的機率
資料產生速度較快時，CPU 若來不及逐筆讀取，新的資料可能覆蓋舊資料。DMA 能依硬體要求迅速搬移。

STM32 內部不只有 CPU 和記憶體，還有許多硬體功能模組：
CPU
SRAM
Flash

其中 ADC、GPIO、TIM、USART 等都稱為：
Peripheral
周邊設備／周邊模組
它們不是一般資料儲存空間，而是各自負責特定硬體功能。
例如：
ADC   → 將類比電壓轉成數位值
TIM   → 計時、PWM
USART → 串列通訊
GPIO  → 控制或讀取腳位

DR 是 ADC 內部的資料暫存器
DR 是：
Data Register
資料暫存器
ADC 完成轉換後，硬體會將 12-bit 結果放入：
ADC1->DR
概念上：
PA1 類比電壓
→ ADC1 轉換
→ 結果寫入 ADC1->DR

每一次 ADC 轉換結果都放在同一個硬體暫存器：
ADC1->DR
DMA 每次都從同一個來源位址讀取：
第 1 筆：ADC1->DR → adc_buffer[0]
第 2 筆：ADC1->DR → adc_buffer[1]
第 3 筆：ADC1->DR → adc_buffer[2]
因此來源位址不可以遞增：
Peripheral Increment = Disable

Normal Mode
DMA 填滿一次陣列後就停止：
adc_buffer[0]
→ adc_buffer[1]
→ ...
→ adc_buffer[15]
→ DMA 停止
要取得下一批 16 筆，CPU 必須重新啟動 DMA。
Circular Mode
DMA 填滿陣列後，自動回到開頭：
adc_buffer[0]
→ ...
→ adc_buffer[15]
→ adc_buffer[0]
→ ...
新資料會逐步覆蓋舊資料，正好符合：
舊的 16 筆已處理或不再需要
→ 可以被下一批資料取代
因此本節希望 ADC 持續取樣時，設定為：
DMA Mode = Circular

continuous Conversion Mode = Enabled
代表 ADC 被啟動一次後，會自動持續進行下一次轉換。
Disabled 時
W06-S02 使用的是單次轉換模式：
CPU 呼叫 HAL_ADC_Start()
→ ADC 轉換一次
→ 結果放入 ADC1->DR
→ ADC 停止
若還要下一筆，CPU 必須再次呼叫：
HAL_ADC_Start(&hadc1);
即使設定為 Enabled，程式仍然要先呼叫啟動函式，例如之後會使用：
HAL_ADC_Start_DMA(...);
設定的意義是：
尚未啟動：
ADC 不工作
啟動一次後：
ADC 自動連續轉換

勾選：
DMA1 channel1 global interrupt
這個中斷的用途是：
DMA 搬完指定數量的資料
→ 產生完成中斷
→ HAL 呼叫 ADC DMA 完成回呼函式
→ CPU 得知 adc_buffer[] 已填滿

這次最重要的順序
MX_DMA_Init()
→ MX_ADC1_Init() : 設定 ADC 如何工作
→ HAL_ADC_Start_DMA() : 真正開始 ADC 轉換與 DMA 搬運
原因是 MX_DMA_Init() 會先開啟 DMA1 的時脈並設定 DMA 中斷。之後 MX_ADC1_Init() 執行 ADC 的底層初始化時，才會設定並連結：
ADC1 ↔ DMA1 Channel 1
如果反過來：
MX_ADC1_Init();
MX_DMA_Init();
ADC 初始化期間可能需要操作 DMA 暫存器，但 DMA 時脈尚未開啟，可能導致初始化失敗或 DMA 無法正常工作。

if (HAL_ADC_Start_DMA(&hadc1,
                      (uint32_t *)adc_dma_buffer,
                      ADC_SAMPLE_COUNT) != HAL_OK)
&hadc1
→ 使用 ADC1
(uint32_t *)adc_dma_buffer
→ DMA 搬入的目的地陣列
ADC_SAMPLE_COUNT
→ 每輪搬移 16 筆資料

建立 CPU 專用的快照陣列
目前有同步風險：
DMA 正在寫 adc_dma_buffer[]
CPU 同時讀 adc_dma_buffer[]
CPU 可能讀到：
前半部＝新一輪資料
後半部＝上一輪資料

Normal Mode 自動停止「DMA 搬運」
HAL_ADC_Stop_DMA() 停止「ADC + DMA 功能」

ADC1 連續產生轉換結果
→ DMA1 Channel 1 自動搬入 adc_dma_buffer[]
→ Normal Mode 搬滿 16 筆後停止
→ DMA 完成回呼只設定 ready 旗標
→ 主迴圈建立穩定快照
→ 重新啟動下一批 DMA
→ 計算 16 筆平均值
→ UART 每秒輸出

ADC 負責產生資料
DMA 負責搬運資料
CPU 負責處理資料
