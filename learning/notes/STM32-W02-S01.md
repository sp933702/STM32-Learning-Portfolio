### [筆記] 2026-07-26 00:00

【STM32-W02-S02：Software Debounce 邏輯理解】

本次使用 PB0 作為 GPIO Input Pull-up，並透過 HAL_GetTick() 實作非阻塞式 20 ms Software Debounce。每次穩定按下 PB0 時，切換一次 PC13 LED；持續按住與放開時不重複切換。

一、三個按鍵狀態變數

1. button_current_raw_state
每一次 while 迴圈直接透過 HAL_GPIO_ReadPin() 讀取到的 PB0 即時狀態。

2. button_last_raw_state
最近一次偵測到的原始候選狀態，也是目前正在接受 20 ms 穩定度驗證的狀態。它可能尚未通過穩定時間的確認。

3. button_stable_state
已經持續滿 20 ms、被程式正式接受的按鍵狀態。

可用以下方式理解：
current_raw：現在讀到什麼？
last_raw：目前正在觀察、驗證什麼？
stable：程式目前正式相信什麼？

button_last_raw_state 與 button_stable_state 不能合併，因為 last_raw 可能只是剛讀到的新狀態，尚未通過 20 ms 驗證；stable 才是已確認的正式狀態。

二、程式執行流程

1. 每一圈先取得目前時間，並讀取 PB0：

current_time = HAL_GetTick();
button_current_raw_state = HAL_GPIO_ReadPin(...);

2. 若目前原始狀態與正在觀察的候選狀態不同：

button_current_raw_state != button_last_raw_state

代表輸入剛發生變化，因此：
- 將 button_last_raw_state 更新成目前狀態。
- 將 button_debounce_start_time 更新成 current_time。
- 從這一刻重新計算 20 ms。

3. 若候選狀態連續維持滿 20 ms：

current_time - button_debounce_start_time >= 20 ms

才認為這個狀態已經穩定。

4. 當 button_stable_state 與 button_last_raw_state 不同時：

button_stable_state != button_last_raw_state

代表這是一個尚未處理過的新穩定狀態，因此將：

button_stable_state = button_last_raw_state;

若兩者已經相同，表示這個狀態先前已經處理過，不需要重複處理。

5. PB0 使用 Pull-up，因此：
- GPIO_PIN_SET：High，未按下。
- GPIO_PIN_RESET：Low，按下。

只有正式接受的新狀態為 GPIO_PIN_RESET 時，才執行：

HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);

因此只在「穩定按下」時切換 LED，穩定放開時只更新狀態，不切換 LED。

三、按下流程範例

初始狀態：
current_raw = SET
last_raw = SET
stable = SET

剛接地時：
current_raw 變成 RESET，與 last_raw 不同。
程式將 last_raw 更新為 RESET，並重新開始計時。
此時尚未滿 20 ms，所以 stable 不更新，LED 不切換。

接地 10 ms：
current_raw 與 last_raw 都是 RESET，因此不重新計時。
因為 10 ms 尚未達到 20 ms，stable 不更新，LED 不切換。

接地滿 20 ms：
current_raw = RESET
last_raw = RESET
stable = SET

時間條件成立，且 stable 與 last_raw 不同，因此：
stable 更新為 RESET，並切換 LED 一次。

繼續按住：
current_raw、last_raw、stable 都是 RESET。
雖然時間條件仍成立，但 stable 與 last_raw 相同，因此不再切換 LED。

放開第一瞬間：
current_raw 變成 SET，last_raw 仍是 RESET。
程式將 last_raw 更新為 SET，並重新開始計算 20 ms。
stable 暫時仍是 RESET，LED 不切換。

放開穩定滿 20 ms：
last_raw = SET
stable = RESET

程式正式接受 SET，將 stable 更新為 SET。
但因為 SET 代表放開，所以不執行 LED Toggle。

四、接點彈跳範例

假設輸入狀態依序是：

0 ms：RESET
3 ms：SET
7 ms：RESET
27 ms：RESET

每次原始狀態改變時都會重新開始計時，因此最後一次計時從 7 ms 開始。

27 ms - 7 ms = 20 ms

RESET 已連續維持 20 ms，因此正式接受 RESET，並切換 LED 一次。前面 0 ms 與 3 ms 的短暫變化不會被當作正式按鍵事件。

五、核心結論

Debounce 時間判斷負責排除短暫彈跳：

current_time - debounce_start_time >= 20 ms

stable_state != last_raw_state 負責避免持續按住時重複處理。

stable_state == GPIO_PIN_RESET 負責只在穩定按下時切換 LED。

整體演算法可濃縮為：

每圈讀取 PB0；若原始狀態改變，就更新候選狀態並重新計時；候選狀態穩定滿 20 ms 且不同於正式狀態時，才接受新狀態；若接受的是 Low，則切換 LED 一次。

實機結果：
- 第一次接地：LED 亮。
- 持續接地：LED 不亂閃。
- 放開接地：LED 保持原狀。
- 第二次接地：LED 熄滅。
- 每次接地只切換一次。
