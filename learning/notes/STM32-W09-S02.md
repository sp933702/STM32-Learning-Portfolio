為什麼要自己定義？
想像有一天你不是使用：
HAL_I2C_Mem_Read()
而是改成：
LL Driver
自己操作 Register
RTOS Driver
甚至另一顆 MCU
底層可能根本沒有：
HAL_OK
HAL_TIMEOUT
但 Application 還是可以繼續看：
DRIVER_OK
DRIVER_TIMEOUT
所以：
HAL_StatusTypeDef
是：
STM32 HAL 的語言
而我們準備建立的：
DriverStatus
是：
我們自己韌體架構的共同語言
這就是 W09-S02 的核心。

如果未來有
MPU6050 Driver
SPI Driver
UART Driver
Flash Driver
它們都要使用同一組：
DRIVER_OK
DRIVER_BUSY
DRIVER_TIMEOUT
DRIVER_ERROR
那這個定義就不應該放在：
main.c
也不應該放在：
mpu6050.h
因為它不是 MPU6050 專屬，而是所有 Driver 共用的狀態型別。
所以我們建立：
Core/Inc/driver_status.h
這是你自己建立的檔案，不是 CubeMX 自動產生的

Step 1：建立 driver_status.h
在 STM32CubeIDE：
Core
└─ Inc
   └─ Header File
檔名：
driver_status.h
先建立 Header Guard：
#ifndef DRIVER_STATUS_H
#define DRIVER_STATUS_H
檔案最後：
#endif /* DRIVER_STATUS_H */
中間才放我們的 enum。

Step 2：建立 DriverStatus
你剛才自己定義了四個狀態，所以寫：
typedef enum
{
    DRIVER_OK = 0,
    DRIVER_BUSY,
    DRIVER_TIMEOUT,
    DRIVER_ERROR
} DriverStatus;

為什麼 DRIVER_OK = 0，其他卻沒指定？
C 的 enum 會自動往下加：
DRIVER_OK      = 0
DRIVER_BUSY    = 1
DRIVER_TIMEOUT = 2
DRIVER_ERROR   = 3
所以：
DRIVER_OK = 0,
DRIVER_BUSY,
DRIVER_TIMEOUT,
DRIVER_ERROR
其實等價於：
DRIVER_OK      = 0,
DRIVER_BUSY    = 1,
DRIVER_TIMEOUT = 2,
DRIVER_ERROR   = 3
我刻意讓：
DRIVER_OK = 0
明確寫出來，是因為在韌體裡常希望：
0 → Success / No Error
非 0 → 某種異常狀態

Driver 內部轉換
概念上：
HAL_I2C_Mem_Read()
        ↓
HAL_TIMEOUT
        ↓
Driver 內部轉換
        ↓
DRIVER_TIMEOUT
        ↓
Application
這樣上層只看到：
DriverStatus
它不需要知道底層到底使用：
STM32 HAL
LL
Register
RTOS API
例如未來底層從：
HAL_I2C_Mem_Read()
換成別的方法，只要 Driver 最後仍然回：
DRIVER_TIMEOUT
Application 就不需要跟著修改。

目前的命名風格：
檔名       → snake_case
driver_status.h
i2c_driver.c
型別名稱   → PascalCase
DriverStatus
enum 成員  → UPPER_CASE
DRIVER_OK
DRIVER_BUSY

為什麼這裡需要 prototype？
假設之後檔案排列：
某個 driver function
{
    convert_hal_status(...);
}

/* 很下面才寫 */
static DriverStatus convert_hal_status(...)
{
    ...
}
編譯器從上往下讀程式時，在第一次看到：
convert_hal_status(...)
之前，就必須先知道：
這個函式存在
輸入是 HAL_StatusTypeDef
回傳是 DriverStatus
所以先放 prototype。

為什麼還需要 default？
我們雖然知道 HAL_StatusTypeDef 正常只有：
HAL_OK
HAL_ERROR
HAL_BUSY
HAL_TIMEOUT
但這個函式宣告：
static DriverStatus convert_hal_status(...)
代表：
不管傳進來什麼，函式最後都應該回傳一個 DriverStatus。
假設某些異常情況傳進來不是這四種值，而 switch 沒有任何 case 命中
