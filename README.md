# STM32 暫存器韌體學習

STM32F103C8T6 從 HAL 改用暫存器重做的學習紀錄，最終作品為「姿態感測資料記錄器」。

- 📒 [學習進度與筆記](learning/README.md)
- ❓ [問題整理（複習用）](learning/QUESTIONS.md)
- 🎤 [面試準備（面試卡彙整）](learning/INTERVIEW.md)
- 💾 各課題程式碼：`projects/SPRINT-Wxx-Sxx/`

## 資料夾結構

```
CLAUDE.md            給 Claude 的背景說明（Claude Code 會自動讀取）
STM32Tracker2.exe    雙擊開啟新版學習進度 App（綠色圖示）
tracker2/            新版 App（只用 Python 標準函式庫）
  prompts/           提示詞規則（改這裡的 md 檔就能調整 Claude 的教法）
  selftest.py        自我檢查：改完 App 後執行 python tracker2/selftest.py
  launcher.cs        STM32Tracker2.exe 的原始碼
  build_exe.bat      產生 STM32Tracker2.exe（第一次使用、或改了 launcher.cs 才需要）
STM32Tracker.exe     舊版 App（藍色圖示），備用
tracker/             舊版 App 的程式，不再修改
docs/                改進計畫等文件
learning/
  progress.json      所有課題、狀態、筆記（App 的資料）
  README.md          進度總覽（自動產生）
  QUESTIONS.md       問題整理（自動產生）
  INTERVIEW.md       面試準備：面試卡與面試版說明（自動產生）
  notes/             每個課題的筆記頁（自動產生）
projects/
  SPRINT-W01-S03/    該課題的程式碼（例如 CubeIDE 專案）
```

## 新版與舊版 App

目前有兩個 App 並行，**共用同一份筆記**（`learning/progress.json`），在哪一邊記的另一邊都看得到。

- 新版 `STM32Tracker2.exe`：提示詞較短、TODO 不會遺失、同步衝突會自動還原並提醒。之後的改進都做在新版。
- 舊版 `STM32Tracker.exe`：新版用起來有問題時的備用。
- 兩個不要同時開啟（新版啟動時會檢查）。
- 新版多了「進度」「待學」「面試」三種筆記類型，在舊版看得到內容但沒有底色。自動產生的 `learning/*.md` 以最後存檔的那個 App 的格式為準。
- 第一次使用新版：雙擊 `tracker2/build_exe.bat` 產生 `STM32Tracker2.exe`。

新版和舊版不同的地方：

- **提示詞分三種**：新課題、接續（同一課換新對話時用）、求助。同一個對話隔天繼續時不用再貼提示詞。
- **提示詞只帶筆記標題**，不再把筆記全文貼回去。
- **待辦 TODO**：筆記裡寫了 `TODO：…` 的行會列在任務頁上方，並帶進之後每一課的提示詞，做完請勾掉。
- **今天到這**：結束前對 Claude 說「今天到這」，把它給的【本次進度】貼進「結束本次課題 → 尚未完成」的欄位，下次的接續提示詞會帶上。
- **同步衝突**：兩台電腦的進度衝突時，App 會還原到同步前的狀態並顯示紅色警告，筆記不會遺失。
- **一次貼上多則**：把 Claude 的整段回覆貼進輸入框按儲存，App 會依 ```` ```markdown ```` 區塊和開頭的【】拆成多則，顯示預覽後一次存入。和舊筆記同標題時可以選「取代舊的」「另存一則」或「略過」。
- **自動分類**：開頭是【筆記】【問題】【解法】【待解決】【本次進度】【待學】【面試】時自動決定類型，沒有才用畫面上選的類型。
- **編輯筆記**：每則筆記有「編輯」按鈕，可以改內容和類型。
- **問題＝踩過的錯**：【問題】不用再勾「已解決」。真正還沒有答案的疑問勾「待解決」（或用【待解決】開頭），它會帶進提示詞並列在複習分頁的「待解決」。
- **待學清單**：【待學】是先不展開的延伸主題，列在任務頁上方，學完勾「已學」。
- **`learning/QUESTIONS.md` 改成只列標題**（待解決的才附全文），全文在各課的筆記頁。
- **課程依階段分組**：基礎、中斷與通訊、DMA 與架構、I²C、SPI、可靠度與整合、求職線、選修。選修和已併入的課題有標示，不計入必修進度。
- **必學範圍**：每課有一份必學項目，學到能不看筆記口頭解釋就勾選。不限每課幾次做完；提示詞會帶上還沒勾的項目，延伸主題則先記成【待學】。
- **進度儀表**：技術必修與求職線的完成數、最近 4 週的學習日數，以及依最近幾課的實際速度推算的技術主線完成日。
- **提示詞依課題類型不同**：暫存器、元件驅動、架構、除錯、觀念、求職各有自己的教法；提示詞也會列出已經寫好的模組介面（從上一課專案的標頭檔擷取）。
- **結束課題**：「尚未完成」改成填「做到哪／下次從哪開始」；「已完成」會顯示完成前檢查（必學範圍、總整理筆記、程式碼、待解決問題），只提醒不擋。
- **關閉 App 時自動結束進行中的這一次**，下次開啟按「繼續」即可。
- **舊計畫（HAL）改為唯讀的「舊紀錄」分頁**。
- **複習**：完成一課後 App 會跳出複習提示詞，貼到 Claude 的新對話，Claude 當面試官口頭考 5 到 8 題（約 15 分鐘）。考完回到 App 記錄結果（順利／部分卡住／需要重看），App 依結果安排下次複習日：間隔 1、3、7、21 天，之後每 45 天一次。到了複習日，任務頁上方會提醒，課題旁邊顯示「待複習」。
- **面試卡**：複習結束時 Claude 會把題目整理成【面試】卡。到那一課的詳細頁按「＋ 新增筆記到這一課」貼上（不用重新開始課題）。所有面試卡會自動彙整到 `learning/INTERVIEW.md`。
- **補做總整理**：已完成但沒有總整理筆記的課題會列在提醒裡，按課題名稱取得提示詞，Claude 會依當時的筆記整理，不重新上課。
- **履歷提醒**：陀螺儀驅動完成後，App 會提醒可以開始履歷初稿（求職線和技術課並行）。

## 使用學習進度 App

下面的步驟兩個版本相同。

需要：Python 3.8 以上、Git。

1. 雙擊 `STM32Tracker.exe`，會開啟一個獨立的 App 視窗（用 Windows 內建的 Edge App 模式，沒有網址列與分頁；背景程式不會出現終端機視窗）。
   - 關閉視窗後，App 會在幾秒內自動結束；也可以按右上角的「關閉 App」。
   - 視窗大小與位置會被記住；GitHub 連結會用你平常的瀏覽器開啟。
   - 如果 exe 不見了，雙擊 `tracker/build_exe.bat` 重新產生（用 Windows 內建的 C# 編譯器，不需要網路）。
   - 發生錯誤時會跳出對話框，紀錄在 `tracker/app.log`。
2. 在任務列表按「開始」（做過的課題顯示「繼續」）→ 狀態變成「進行中」，並跳出**開始提示詞**：複製後貼到 Claude，Claude 會依完成標準一步一步帶你（之後可在進行中的卡片按「📋 開始提示詞」再取得）。
3. 過程中隨時記下「問題／筆記／解法」（Ctrl + Enter 儲存）。卡住時按「🆘 求助提示詞」，描述卡在哪裡，App 會附上課題資訊、筆記與程式碼產生求助提示詞。
4. 程式碼：
   - 按「開啟資料夾」直接在 `projects/<課題代碼>/` 建立 CubeIDE 專案，或
   - 用「上傳檔案」「上傳整個資料夾」或拖曳，把程式碼放進該課題資料夾（`Debug/`、`.o`、`.elf` 等會自動略過）。
5. 按「結束本次課題」→ 自動 commit 筆記與程式碼並 push 到 GitHub：
   - **已完成**：總結寫入課題，加上 tag（例如 `SPRINT-W01-S03`）。
   - **尚未完成**：本次進度記成一則【本次進度】筆記，下次的開始提示詞會帶上它；不打 tag。
   - **卡關**：必須描述卡在哪裡，記成一則未解決的【卡關】問題，並跳出求助提示詞。
6. 換電腦時先按「⟳ 同步」（App 啟動時也會自動同步）。

自己 commit 程式碼時，在訊息裡寫上課題代碼（例如 `SPRINT-W02-S04: 加入 ORE 處理`），App 的任務詳細頁就會列出這些 commit，並連到 GitHub。

## 在其他裝置複習

push 到 GitHub 後，用手機或任何電腦打開 repo 的 `learning/README.md` 或 `learning/QUESTIONS.md` 就能閱讀所有筆記；面試前看 `learning/INTERVIEW.md`。
